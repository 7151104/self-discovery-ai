## Журнал закрытых задач

Строго дописывающий раздел: одна задача — одна строка, строка начинается с
идентификатора, блоки по этапам маршрута. Что именно проверялось при закрытии —
в критерии приёмки задачи в `docs/13-roadmap.md`.

### E2 · Движок до полного контура

- **E2-01** — `content/questions-full-bank.md` переразмечен в таблицу из семи колонок (идентификатор, текст, тип, координаты, направление, роль, варианты): варианты вынесены из ячейки с текстом вопроса, направление и роль перестали быть пометками в скобках, идентификаторы приведены к `Q1`–`Q35` и `О1`–`О3`. Сборщик разбирает банк и падает при любом расхождении формата; формулировки не изменились ни в одном символе — это проверяется сборкой строки таблицы обратно и отсутствием следов разметки, а не контрольным списком текстов в коде
- **E2-02** — скоринг полного банка: инверсия обратных, среднее, полоса, разброс и confidence вынесены в одну функцию `scoreCoordinate`, ветка лестницы переведена на неё без изменения своих правил, ветка банка написана на ней же. Правила — в `content/scoring-rules.md`, раздел «Полный банк: точные правила». На ответах демо-человека пустыми остаются только координаты 15 и 16: открытый текст движок не разбирает

### E5 · Тексты и контент

- **E5-04** — промежуточные блоки прикладных срезов: 25 пар S4×S5 в `content/slices/work.md`, 20 пар в `content/slices/relationships.md`. Тексты опираются только на ответы первой порции, второй порции не обещают и вопросов не пересказывают; покрытие пар и регистр речи проверяет `engine/src/content-slices.test.ts`

- **E5-01** — реестр запрещённых формулировок: `content/forbidden.md` — 16 групп, у каждой своя степень запрета и область действия, плюс общий список формулировок-исключений и раздел о том, что лексикой не ловится. Сопоставление — `engine/src/forbidden.ts`; два теста `engine/src/content.test.ts` переведены с регулярок на реестр и проходят
- **E5-08** — юридические тексты: `content/legal/` — политика, согласие, оферта и реестр из 11 дисклеймеров с местами показа. Реквизиты — подстановки, список в `content/legal/README.md`; немедицинский дисклеймер стоит на входе, на оплате и в подвале, а не только в подвале; проверка — `engine/src/content-legal.test.ts`

## Принятые решения

Журнал. Не переоткрывать без явного запроса основателя. Блоки — по областям, а не по
этапам: решение живёт дольше этапа, в котором принято. Дописывать — в конец таблицы
своей области.

### Архитектура и код

| Решение | Обоснование |
|---------|-------------|
| Markdown — единственный источник правды; код его только читает | Интеллект продукта в текстах и правилах, а не в коде. Сборщик `engine/scripts/build-content.mjs` превращает `content/*.md` в типизированные данные, поэтому правка текста не требует правки кода |
| Условия срабатывания узлов и арифметика скоринга живут в коде, не в прозе | Прозой они однозначно не записываются. Компенсация: тесты сверяют состав и порядок узлов в коде с `content/step3-contradictions.md`, а состав полос карты — с таблицей в `docs/11-ui-page-spec.md` |
| Генерируемый `engine/src/generated/` не хранится в репозитории | Он производная от markdown; хранение создаёт второй источник правды. Пересборка входит в `npm test` и `npm run serve` |
| Ступени 1–3 — только lookup, без LLM | Данных мало, LLM на них льёт воду; нужна мгновенность и предсказуемость. Ступень 4 и платное — LLM |
| Координаты наружу не отдаются: клиент получает блоки, полосы, двери и предложение | Значения координат, `confidence` и машинные коды — внутренняя тайна продукта. Закреплено тестом: сериализованное состояние страницы не содержит `confidence` и кодов вида `at_80` |
| Карта показывает 7 полос из 16 координат | Полная карта — платный продукт; остальные девять координат видны как отсутствие. Это и есть закрытые двери |
| Лестница честно оставляет шесть координат пустыми (1, 6, 10, 12, 14, 16) | Не дефект, а устройство бесплатного входа. Тест фиксирует именно этот список, чтобы «улучшение» скоринга не заполнило их догадками |
| Дата рождения не участвует в скоринге вообще | Эшелон 3 не имеет права утверждать. Тест проверяет, что источники координат — только ответы лестницы |
| Сезон темы периода берётся по текущей дате, а не по дате рождения | Тема периода — про «сейчас», а не про человека. Дата рождения нужна для карточки и визуала |
| Тема периода не записывается в координату 16 | Иначе метафора просочится в утверждение. Живёт отдельным полем оформления |
| Один узел на ступени 3, остальные — закрытые двери | Один механизм читается, три размываются. Приоритет: расхождение самооценки и поведения → узел с уязвимостью → остальные |
| Узел не выдумывается: есть `NODE_NONE` | Если ни одна пара не сработала, честный текст сильнее подогнанного узла |
| Поведение важнее самооценки: значение берётся из поведенческого ответа, самооценка даёт флаг | Правило 2 из `docs/04-alignment-rules.md`. Расхождение — материал для раздела напряжения, а не шум |
| Цена показывается только у предложенной двери | Остальные платные двери без цен, иначе маршрут читается как витрина |
| `NODE_POTENTIAL_VS_DETAIL` ведёт сразу в прикладной срез за 1290 ₽ | Узлового среза под него нет, а срез «Работа и реализация» допускается первым предложением. Кандидат на проверку: при низкой конверсии в 1290 ₽ первым чеком написать под узел срез за 590 ₽ |
| Открытый ответ короче 15 слов не даёт ни блока, ни предложения | Синтез на двух словах — вода. Порог проверяется тестом |
| Числа вопросов, цены и темы в текстах предложений — подстановки, а не литералы | Источник — таблица в `content/slices/README.md`, движок отдаёт их полями оффера (`engine/src/offers.ts`). Литерал в шаблоне разъезжается с контентом при первой правке добора |
| Прототип без сборщика: ванильный ES-модуль плюс статический сервер без зависимостей | Проверялся сценарий, а не стек. Прототип не является продакшен-фронтом и будет заменён в E7 |
| Состояние прототипа лежит в `localStorage` | Временное решение до появления сервера (E3). В целевом состоянии локально хранится только черновик текущего ответа |
| TypeScript в строгом режиме, тесты на `node:test`, без внешних фреймворков | Две зависимости на весь проект; движок обязан оставаться переносимым |
| Направление вопроса в банке задаётся относительно группы вопросов его основной координаты, а не относительно порядка полюсов в `docs/02-coordinates.md` | Порядок полюсов в `docs/02` со знаком координаты совпадает не везде (4, 5, 11), а внутри группы вопросов пометки «прямой/обратный» согласованы. Арифметике нужна именно согласованность внутри группы; какой полюс считать верхним — решает код по координате |
| Полоса координаты растёт в сторону второго полюса из `docs/02-coordinates.md`; исключение — координата 5 | У координаты 5 полоса растёт к «определённости», это уже заложено в правилах лестницы, а карта разворачивает её при показе (`engine/src/map.ts`). Переворачивать координату ради красоты — переписывать правила лестницы |
| Контрольного списка текстов вопросов в коде нет: неизменность формулировок проверяется сборкой строки таблицы обратно и отсутствием следов разметки | Список текстов в тесте — второй источник правды; при калибровке банка (E5-11) он потребовал бы правки кода на каждую правку текста |
| `Q26` помечен обратным относительно группы координаты 11, хотя в `docs/02-coordinates.md` пометки у него нет | В группе координаты 11 прямой полюс задаёт `Q23` («довожу»), а `Q26` («не сдвинусь без внешнего срока») смотрит в обратную сторону. `docs/02` — документ архитектуры, пометку в нём не дописываем: банк остаётся источником направления, а `docs/02` — источником состава координат |
| Роль `ключевой` у `Q34` записана в банк | В `docs/02-coordinates.md` она указана, в банке её не было. Тест теперь сверяет роли банка с `docs/02` |
| Арифметика скоринга — одна функция `scoreCoordinate`, обе ветки входа обязаны ходить в неё | Два входа в один скоринг иначе расходятся в два набора правил. Потолки confidence лестницы вынесены в отдельную таблицу по контенту и накладываются поверх общего расчёта |
| Координаты 15 и 16 заполняются только структурированным результатом синтеза открытых ответов | Движок текст не интерпретирует: это работа LLM (E4-07). Без синтеза координаты честно остаются пустыми — как и в лестнице |
| Координата 14 считается голосами категорий, а не средним | «Способ решать» — не шкала, а четыре режима (анализ, отклик, обсуждение, пауза); усреднять их бессмысленно. Голос — ответ в верхней полосе или названный вариант; ответ за другую категорию считается спорящим |
| Код координаты 13 у лестницы и у банка разной точности (`needs_external_pull` против `invited` / `on_request` / `many_tries`) | В лестнице ключевого вопроса координаты нет, есть только косвенный `L11`; выдумывать точность нельзя. Единый словарь подтипов сводится в E2-04 |
| Общее правило «середина полосы и противоречия → low» применено в общей арифметике, включая ветку лестницы | Иначе появляется второй набор правил. На непокрытых входах лестницы это меняет medium на low в нескольких сочетаниях; на продукт не влияет — карта различает только `high`, остальное показывается как «предположение» |
| Расхождение с ожиданиями в `examples/demo-person-answers.md` по координатам 8 и 9 (medium вместо high) не правится | Уязвимость демо-человека подтверждается его открытыми ответами, а подтверждение текстом считает только LLM; по координате 9 `Q21` спорит с ключевым `Q20`, и это честный medium. Файл — заметка к демо, а не приёмка |

### Контент и тексты

| Решение | Обоснование |
|---------|-------------|
| Два бесплатных отчёта разведены по именам: **финал лестницы** (`финал_лестницы`, 250–350 слов, три абзаца) и **полный бесплатный разбор** (`бесплатный_полный`, 900–1200 слов, семь частей без п.5). Подтверждено основателем | Одно имя носили разные сущности с разным каркасом и объёмом втрое. Тип отчёта — часть контракта с LLM и вход валидатора объёма: по общему имени он не смог бы выбрать порог |
| В «Пяти сшивках» (`docs/02-coordinates.md`) номера — это координаты; префикс `Q` означает только номер вопроса. Подтверждено основателем | Единственное чтение без противоречий: при чтении номеров как вопросов четыре из пяти не относятся к называемым темам. Смысл сшивок не менялся, менялась запись |
| Файл доборов `slice_full_map` (E5-13) не повторяет формулировки банка, а перечисляет идентификаторы `Q…` и `О…` в порядке порций | Копия текста делает у одного вопроса два источника, и они разъезжаются на первой калибровке банка (E5-11). Текст вопроса живёт только в `content/questions-full-bank.md` |
| Подписи дверей живут в отдельном `content/doors.md`, а не в `content/step3-contradictions.md` | Подписи нужны странице раньше первого узла (маршрут виден с первого экрана) и покрывают срезы, к которым узел не ведёт вовсе: полная карта, развилка, точки трения. `step3-contradictions.md` — lookup одной ступени, двери живут на странице от входа до последнего платного блока |
| Три реестра подписей: по узлу, прикладная дверь под узел, общая по срезу | Дверь узлового среза подписывается механизмом, прикладная — тем же механизмом в области жизни («как это работает в близких»), а до ступени 3 тема человеку не известна и подпись общая. Прочерк в прикладной таблице означает «берётся подпись узла» и допускается только там, где это собственный срез узла — иначе у одной двери было бы две подписи |
| Тексты этапа E5 собираются во второй производный файл `engine/src/generated/content-extra.ts` | Партии текстов E5 идут независимо друг от друга; отдельный файл и отдельный блок в сборщике позволяют добавлять раздел, не переписывая уже собранное |
| Юридические реквизиты — только места для подстановки, без правдоподобных заглушек | Выдуманный ИНН опаснее пустого места: заглушку легко не заметить при публикации. Полный список — `content/legal/README.md` |
| Сроки удаления данных в политике не названы числом | Хранения ещё нет (E3), удаления профиля тоже (E9-05). Обещать непроверенный срок — юридическая гарантия, которой продукт не даёт |
| Реестр запретов различает три степени: `жёсткий` (совпадение всегда ошибка), `по контексту` (законно под отрицанием или в перечисленных исключениях), `подозрение` (линтер показывает, решает человек) | Одноуровневый список ругается на законные употребления — «не является диагнозом», «это не лень, а способ», «предсказаний здесь нет» — и его выключают. Форма степени `по контексту` не может содержать отрицание внутри себя: сборщик это проверяет, иначе запрет никогда не срабатывает |
| Степень и область принадлежат группе реестра, а не отдельной форме | Иначе одна форма получает два разных запрета в разных строках и линтер перестаёт быть правилом. Область отделяет разбор от вопросов: «выгорание» запрещено в разборе и законно в варианте ответа, где это слово человека |
| Кризисный дисклеймер объясняет только отсутствие разбора, полный кризисный текст — за E5-02 | Иначе один и тот же текст жил бы в двух файлах. `{{КОНТАКТЫ_ПОМОЩИ}}` заполняется из `content/crisis.md` |

### Продукт и маршрут

| Решение | Обоснование |
|---------|-------------|
| Отдельного бесплатного входа на полный банк 35+3 в первом релизе нет. ## Как обновлять этот файл

Этот файл и `docs/13-roadmap.md` правят несколько агентов из разных веток, и правят чаще
всего остального. Правила ниже нужны ровно для одного: чтобы параллельные правки
сливались сами. Они выполнимы вручную, инструментов не требуют.

**1. Строка принадлежит задаче.** Всё, что дописывается сюда, начинается с идентификатора
задачи (`E2-03 — …`). Работа шла вне маршрута — вместо идентификатора короткое имя темы,
а строка идёт в блок «Вне задач маршрута».

**2. Чужие строки не трогаем.** Не переписываем, не переставляем, не сортируем, не
удаляем. Даже ради порядка. Исправлять чужую строку можно, только когда она стала
неправдой, — отдельным коммитом и с объяснением в сообщении коммита.

**3. Дописываем снизу и только в свой блок.** «Журнал закрытых задач» разбит по этапам,
«Принятые решения» — по областям, «Текущая точка» — по потокам. Строка идёт в конец блока
своего этапа или своей области. Параллельные потоки почти всегда находятся в разных
блоках (движок — E2, сервер — E3, контент — E5), их правки попадают в разные места файла
и сливаются без конфликта.

**4. Нужного блока нет — завести его.** Этапы идут по возрастанию, области — в порядке
списка; блок «Вне задач маршрута» всегда последний в журнале. Это единственная допустимая
правка за пределами своей строки.

**5. «Текущая точка».** Агент правит только строку своего потока. Число тестов в строке
проверки меняет тот, кто менял тесты.

**6. Открытые вопросы нумеруются один раз.** Закрытый вопрос убирается из таблицы,
остальные не перенумеровываются: на номера ссылаются другие документы. Новый вопрос
получает следующий свободный номер.

**7. Если конфликт всё-таки случился** (два агента закрывали задачи одного этапа) — он
разрешается механически: сохраняются обе стороны, порядок — по идентификатору. Ничей
текст не выбрасывается и не переписывается.

**Закончив задачу:** поменять её статус в `docs/13-roadmap.md`, дописать строку в «Журнал
закрытых задач» здесь, обновить строку своего потока в «Текущей точке». Решение, которое
пришлось принять по ходу, — одной строкой в «Принятые решения», в блок своей области.
Вопрос, который не удалось решить, не ломая архитектуру, — в «Открытые вопросы к
основателю».

**`docs/13-roadmap.md` — по тем же правилам.** Агент правит строку `**Статус:**` только
своей задачи. Новая задача добавляется в конец своего этапа со следующим свободным
номером; существующие задачи не перенумеровываются, даже если между ними появились
пропуски. Счётчик задач в «Карте маршрута» и в `AGENT-BOOTSTRAP.md` меняет только тот,
кто задачу добавил или убрал.
