# 12. Итоговое состояние: что значит готово на 100%

Документ отвечает на один вопрос: по каким признакам можно однозначно сказать «дошли» или
«не дошли». Это не список пожеланий, а приёмочный лист. Маршрут к этому состоянию —
`docs/13-roadmap.md`, текущая точка — `docs/14-state.md`.

**Правило чтения.** Критерий готовности сформулирован так, чтобы его можно было закрыть
одним из трёх способов: команда в терминале, автотест или взгляд на экран. Формулировки
вида «интерфейс аккуратный» в этом документе запрещены — если критерий нельзя проверить,
он переписан или удалён.

**Что не меняется.** 16 координат как внутренний язык, лестница входа из 4 ступеней,
три эшелона моделей, 8 правил согласования, два закона продукта. Целевое состояние — это
полная реализация этой архитектуры, а не её ревизия.

**Готово на 100%** = все чеклисты слоёв 1–9 закрыты и приёмка по разделу «Условие перехода
к живым людям» подписана. Ни один слой не является необязательным.

## Слои целевой системы

| # | Слой | Что считается результатом слоя |
|---|------|-------------------------------|
| 1 | Контент и продуктовые правила | Все тексты, которые видит человек, существуют в `content/` и `prompts/`, а не в голове агента |
| 2 | Движок координат | Любой набор ответов (лестница, полный банк, доборы) превращается в профиль, узел, порог и предложение без участия LLM |
| 3 | Серверная часть и хранение | Личная страница живёт по постоянной ссылке и переживает перезагрузку, закрытие браузера и смену устройства |
| 4 | LLM-слой | Ступень 4 и платные срезы генерируются автоматически, с валидацией выхода и кризисным контуром |
| 5 | Интерфейс и визуал | Страница выглядит и ведёт себя как в `docs/11-ui-page-spec.md`, на телефоне в первую очередь |
| 6 | Оплата и маршрут | Человек может заплатить, сразу получить вопросы, потом отчёт; заказ и доступ управляются состоянием |
| 7 | Юридика, приватность, безопасность | Согласие, документы, удаление данных, кризисный протокол, отсутствие утечек профиля |
| 8 | Инфраструктура, деплой, наблюдаемость | Сервис поднимается с нуля одной командой, деплоится автоматически, ошибки и воронка видны |
| 9 | Качество и тесты | Сквозной путь и визуал закрыты автотестами; контент проверяется линтером на каждом коммите |

## Слой 1. Контент и продуктовые правила

**Результат.** Ни одна строка, которую видит пользователь, не рождается в коде или в
переписке с агентом. Markdown в `content/` и `prompts/` — единственный источник правды;
код его читает (`engine/scripts/build-content.mjs`).

### Definition of Done

- [x] `content/questions-ladder.md` — 12 вопросов лестницы, разбирается сборщиком, тест на состав и порядок проходит
- [x] `content/questions-full-bank.md` — 40 закрытых и 3 открытых, машинно-читаемый формат, разбирается сборщиком
- [x] Известные проблемы банка из его же раздела закрыты: Q35 подтверждается открытыми, Q31 заменён поведенческим, у координат 1, 4, 12 есть третий вопрос
- [x] Тексты ветвей ступеней 1–2 покрывают каждый вариант каждого вопроса; тест падает при пропуске
- [x] Шкальные ветви покрывают все пять значений
- [x] Узлы ступени 3: у каждого есть условие, текст и платное предложение, существующее в `content/slices/`
- [x] Доборы всех срезов целевого объёма написаны, у каждого есть скоринг, порог генерации, состав отчёта и запреты
- [x] Доборы `slice_full_map` собраны из остатка полного банка (24 закрытых + `О2`, `О3`) отдельным файлом: порядок вопросов, три порции, промежуточные блоки, порог, состав отчёта и запреты; формулировки не копируются — в файле стоят идентификаторы банка
- [x] Промежуточные lookup-блоки прикладных срезов (после первой порции из десяти) написаны текстами, а не описаны
- [x] Кризисные тексты и контакты помощи написаны отдельным файлом и подключены к движку
- [x] Микрокопия интерфейса собрана в один реестр: каждая строка UI имеет идентификатор и текст, в коде нет зашитых русских строк
- [x] Тексты писем (ссылка на страницу, чек, готовность среза, возврат) написаны в `content/emails.md`; у каждого письма названо место на странице, которое говорит то же самое без почты
- [x] Эталонный текст есть на каждый платный срез: один прогон на демо-профиле, сохранён в `examples/`
- [x] Реестр запрещённых слов, методик и Barnum-шаблонов существует в машинном виде и используется линтером
- [x] `npm test` проходит после правки любого файла в `content/` без изменений в коде

### Чем проверяется

`npm test` (целостность контента и кода), `npm run lint:content` (запрещённые формулировки),
наличие файлов.

## Слой 2. Движок координат

**Результат.** Движок закрывает весь контур данных: лестница, полный банк, доборы срезов,
пороги генерации, кризисный детектор, пересчёт при изменении ответа. LLM в этом слое не
участвует — он получает от движка готовое задание.

### Definition of Done

- [x] Лестница 11+1: 16 координат, шесть остаются `unknown` — тест фиксирует именно этот список
- [x] Полный банк: все 16 координат получают значения, обратные вопросы инвертируются, confidence считается по общим правилам `content/scoring-rules.md`
- [x] Доборы каждого среза разбираются из `content/slices/*.md` и питают координаты по разделу «Скоринг доборов» этого же файла
- [x] Подтипы координат из срезов (например `pre_show_polish`, `post_feedback_stall`) вычисляются кодом и попадают в профиль
- [x] Порог генерации среза — машинное правило: не взят → движок отдаёт уточняющие вопросы, а не отчёт; тест на оба исхода
- [x] Порции доборов: 590 ₽ — одна порция, 1290 ₽ — две по десять с промежуточным блоком между ними, 1990 ₽ (`slice_full_map`) — три порции
- [x] Добор `slice_full_map` собирается движком как вопросы банка без ответа плюс `О2` и `О3`; вопрос, на который человек уже отвечал, в порцию не попадает — тест на профиле после лестницы и после купленного среза
- [x] Правило расхождения работает на всех парах «самооценка + поведение», флаги попадают в раздел напряжения
- [x] Кризисный детектор — чистая функция от открытого текста: возвращает решение «не генерировать» и причину; тест на наборе триггеров и на наборе ложных срабатываний
- [x] Несогласие пользователя с блоком понижает confidence затронутых координат и фиксируется как данные
- [x] Изменение ответа пересчитывает профиль и перезаписывает бесплатные блоки; купленные блоки не переписываются, к ним добавляется отметка о расхождении
- [x] Версии профиля хранятся: можно получить состояние на момент любой покупки
- [x] Селектор следующего предложения после платного среза работает по таблице «следующие двери» из файла среза
- [x] Ни одно правило скоринга не существует только в коде: каждое имеет строку в `content/scoring-rules.md` или в файле среза, тест сверяет состав

### Чем проверяется

`npm test`. Доля покрытия для `engine/src` — не ниже 90% по строкам, замер в CI.

## Слой 3. Серверная часть и хранение

**Результат.** Страница — не локальный прототип, а серверное состояние по постоянной
ссылке `/p/{profile_id}` без обязательной регистрации.

### Definition of Done

- [x] Контракт API описан машинно (схема или типы), клиент и сервер собираются из одного описания
- [x] Схема хранения покрывает: профиль, ответы по вопросам, версии профиля, блоки, заказы, события, несогласия
- [x] Миграции применяются командой и откатываются; чистая база поднимается с нуля одной командой
- [x] Ответы сохраняются после каждой порции; повторная отправка той же порции не создаёт дубля
- [x] Наружу отдаются только блоки, полосы, двери и предложение; в ответе API нет `value`, `band`, `confidence`, `code`, `flags` и названий координат — проверяется автотестом на всех состояниях `s0`–`paid_done`
- [x] Возврат по ссылке через сутки открывает ту же страницу и ту же незакрытую порцию
- [x] Публичный режим просмотра скрывает блоки 3 и 4 и не отдаёт их по API вообще, а не только не рисует
- [x] Приватность по умолчанию: пока человек не нажал «Поделиться», публичная ссылка не работает
- [x] Идентификатор профиля не перебираем: длина и энтропия исключают угадывание, есть ограничение частоты запросов
- [x] Секреты только в переменных окружения; в репозитории нет ни одного ключа, проверяется сканером на CI
- [x] Анонимная идентичность склеивается с оплатой: после платежа доступ привязан к профилю, а не к сессии браузера

### Чем проверяется

Интеграционные тесты API, миграции на чистой базе, автотест «профиль наружу не течёт».

## Слой 4. LLM-слой

**Результат.** Ступень 4 и платные срезы генерируются без участия человека, выход
проверяется автоматически, кризис перехватывается до генерации.

### Definition of Done

- [x] Адаптер провайдера изолирован: смена провайдера не трогает продуктовый код, есть таймауты, повторы и лимит стоимости на профиль
- [x] Промпт ступени 4 собирается из `content/step4-open-synthesis.md` и профиля; в промпте нет ни одного названия методики
- [x] Генерация асинхронная: страница показывает стабильное состояние ожидания, повторный запрос не создаёт второй генерации
- [x] Валидатор выхода отклоняет текст с запрещёнными словами, названиями методик, объёмом вне диапазона и Barnum-шаблонами; при отклонении — повторная генерация, при повторном провале — честное состояние без выдачи текста
- [x] Соответствие регистров confidence проверяется автоматически: утверждение при `low` — отклонение
- [x] Платные срезы собираются как «ассемблер + надстройка среза + порог»; надстройки берутся из `prompts/paid-slice-templates.md`
- [x] Кризисный контур: детектор до генерации, кризисный текст вместо блока, предложение не показывается вообще; тест на сквозном пути
- [x] Координата 15 приходит из синтеза ступени 4 структурировано (текст сюжета + машинный код), а не свободным текстом
- [x] Открытые ответы не могут перехватить инструкцию: тест с попыткой инъекции показывает, что промпт устоял
- [x] Стоимость и время каждой генерации пишутся в журнал; себестоимость профиля видна в метриках
- [x] Один и тот же вход не оплачивается дважды: результат кэшируется, ручная регенерация возможна и помечается
- [x] Недоступность провайдера не теряет ответы: человек видит честное состояние, генерация доигрывается позже

### Чем проверяется

Интеграционные тесты с поддельным провайдером, тест валидатора на корпусе плохих текстов,
кризисный сквозной тест, тест на инъекцию.

## Слой 5. Интерфейс и визуал

Этот слой раскрыт подробнее остальных: визуальная часть — единственный канал роста, который
у продукта есть (`docs/10-business-context.md`), и она должна быть закрыта полностью до
любых живых людей.

### 5.1. Дизайн-система

- [x] Токены существуют как единственный источник: типографика, цвет, сетка, отступы, радиусы, тени, длительности анимаций
- [x] В стилях нет ни одного литерального цвета и ни одного отступа вне шкалы — падает линтер стилей на CI
- [x] Типографическая шкала: не более шести размеров текста и трёх начертаний; каждый размер имеет назначение и используется
- [x] Шкала отступов кратная, не более семи ступеней; вертикальный ритм блока един по всей странице
- [x] Палитра: не более трёх смысловых цветов плюс нейтральная шкала; акцент используется только для действия и для активного маркера карты
- [x] Каждый интерактивный компонент имеет описанные и реализованные состояния: покой, наведение, фокус с клавиатуры, нажатие, выбранное, отключённое, ошибка, загрузка
- [x] Витрина компонентов открывается по внутреннему адресу и показывает все компоненты во всех состояниях на одном экране
- [x] Тёмная тема либо реализована на токенах, либо явно объявлена вне цели в разделе «Границы» — объявлена вне цели

### 5.2. Визуальная карта как виральный объект

- [x] Ровно семь полос, состав и подписи совпадают с таблицей в `docs/11-ui-page-spec.md`; тест сверяет код с документом
- [x] Три состояния полосы визуально различимы без цвета (контур, размытый маркер, чёткий маркер) — проверяется в градациях серого
- [x] Категориальная полоса «Что задевает» показывает семь вариантов, из них подсвечен один
- [x] Ни цифр, ни процентов, ни названий координат, ни названий методик — проверяется автотестом по отрендеренному тексту
- [x] Карта целиком помещается в область 360×640 без скролла
- [x] Пустая полоса кликабельна и объясняет, чем откроется, текстом из `content/`
- [x] Маркер приезжает из центра один раз за 400–600 мс, при повторном скролле не анимируется
- [x] Карта читаема при 200% масштабе текста и не ломает вёрстку

- [x] Содержимое и подписи картинки написаны: `content/share.md` — три слоя, три подписи, два формата; имя продукта и домен стоят подстановками, и без них картинка не собирается (E5-10)

- [x] Картинка генерируется на сервере в двух форматах: 1200×630 и 1080×1350
- [x] На картинке только фраза-крючок, карта и домен; блоков разбора нет
- [x] Шрифты вшиты в генератор: картинка одинакова на любом устройстве
- [ ] Предпросмотр корректно раскрывается минимум в трёх мессенджерах и одной соцсети (проверка вручную, скриншоты сохранены)

- [x] Ни одного модального окна на пути прохождения лестницы
- [x] Безопасные зоны учтены: нижняя панель не перекрывается системными элементами
- [x] Горизонтального скролла нет ни на одном состоянии ни на одной проверенной ширине

- [x] Отказ от оплаты: страница остаётся полной, повторного предложения в тот же визит нет
- [x] Изменение ответа: блоки перезаписываются с пометкой «обновилось»
- [x] Ошибка сети при отправке порции: ответ не теряется, повтор не создаёт дубля
- [x] Несуществующий или отозванный профиль: понятная страница без технических деталей

### 5.8. Доступность

- [x] Контраст основного текста не ниже 7:1, вспомогательного не ниже 4.5:1 — на всех состояниях
- [x] Автоматическая проверка доступности проходит без нарушений на состояниях `s0`–`paid_done`
- [x] Вся лестница проходится с клавиатуры без мыши; фокус виден всегда; порядок фокуса совпадает с визуальным
- [x] Скринридер зачитывает текст вопроса, вариант ответа и позицию внутри порции
- [x] Шкала доступна как группа радиокнопок с подписями полюсов, а не как набор точек без имён
- [x] Карта имеет текстовую альтернативу: словами, без чисел и процентов
- [x] Смысл нигде не передаётся только цветом
- [x] Масштаб текста 200% не ломает ни одно состояние
- [x] Язык страницы объявлен, заголовки идут по уровням без пропусков

### 5.9. Производительность

- [ ] LCP не выше 2.0 с и CLS не выше 0.05 на эмуляции среднего телефона и 4G, замер в CI как бюджет
- [x] Вес первой загрузки: не больше 150 КБ скриптов и 30 КБ стилей после сжатия
- [x] Шрифты не вызывают перескока текста: подмена без сдвига layout
- [x] Ступени 1–3 отдаются без обращения к LLM и без второго круга запросов
- [x] Ответ API на состояние страницы не медленнее 300 мс на 95-м процентиле
- [x] Бюджеты производительности зафиксированы в конфиге и ломают сборку при превышении

### 5.10. Проверочный список «чего не делаем»

Реализуется как автотест по отрендеренной странице, а не как памятка:

- [x] Не показано общее число вопросов
- [x] Нет процентов, баллов и формулировок «твой тип»
- [x] Нет названий методик ни в интерфейсе, ни в подписях, ни в атрибутах
- [x] На первом шаге оплаты одна платная дверь и одна цена
- [x] Нет таймеров, счётчиков мест, зачёркнутых цен, отзывов и звёзд
- [x] Нет имитации «ИИ печатает» на ступенях 1–3
- [x] Нет поздравлений с прохождением и просьб оценить сервис до выдачи разбора

## Слой 6. Оплата и маршрут монетизации

**Результат.** Человек может купить срез, сразу получает вопросы, потом отчёт. Доступ
и заказ управляются состоянием, а не доверием к клиенту.

### Definition of Done

- [ ] Платёжный провайдер подключён, оплата проходит на реальном домене
- [x] Заказ — это состояние: создан, оплачен, провален, возвращён; переходы логируются
- [x] Вебхуки идемпотентны: повторная доставка не выдаёт доступ дважды и не пишет второй чек
- [x] Сразу после оплаты человек видит вопросы, а не отчёт (Закон 2), — проверяется сквозным тестом
- [x] Доступ к платному блоку невозможно получить без оплаченного заказа: попытка обращения к API возвращает отказ
- [x] Повторная оплата того же среза невозможна
- [ ] Чек и оферта доступны из потока оплаты, а не только из подвала
- [x] Возврат средств возможен и отзывает доступ
- [x] После закрытия среза второе предложение выбирается по таблице «следующие двери» из файла среза
- [x] Одна цена на экране на первом шаге оплаты; остальные платные двери без цен
- [x] Тестовый режим оплаты позволяет прогонять платный путь в CI без реальных денег
- [x] Цены в интерфейсе берутся из `content/slices/README.md`, а не зашиты в код

## Слой 7. Юридика, приватность, безопасность

### Definition of Done

- [x] Согласие на обработку персональных данных собирается в потоке до первого сохранения ответов
- [x] Политика обработки данных, оферта и дисклеймеры опубликованы отдельными страницами и связаны из потока
- [x] Дисклеймер «не медицинская и не психологическая помощь» присутствует в продукте, а не только в подвале
- [x] Человек может удалить свой профиль и получить выгрузку своих данных; удаление действительно удаляет, проверяется тестом
- [x] Журналы не содержат открытых ответов, имён и дат рождения; проверяется тестом на образцах логов

- [x] Дата рождения не участвует ни в одном выводе о личности — тест на изоляцию даты от скоринга
- [x] Названия методик и торговые марки отсутствуют во всём, что уходит на клиент
- [x] Открытые ответы и профили шифруются при хранении либо решение об отказе от шифрования зафиксировано в `docs/14-state.md` с обоснованием
- [x] Детские отчёты, компетенции терапии и вердикты совместимости не реализуемы в интерфейсе: соответствующих путей нет

## Границы: что в область цели НЕ входит

Отложено сознательно. Не признак незавершённости, а решение о составе первого полного
релиза. Пересматривается только по запросу основателя.

| Вне цели | Почему |
|----------|--------|
| Мобильные приложения | Продукт — живая страница по ссылке; приложение не добавляет ни виральности, ни удержания на этом этапе |
| B2B white-label для практиков | Параллельный канал (`docs/07-monetization-route.md`); требует отдельного контура брендирования и биллинга практика |
| Другие языки | Рынок первого релиза — русскоязычный; локализация ломает калибровку текстов, пока они не проверены на первом языке |
| Детские отчёты | Отдельный контур сбора (наблюдения родителя) и отдельные юридические ограничения (`docs/08-legal-safety.md`) |
| Бесплатный вход на полный банк 40+3 и отчёт `бесплатный_полный` как продукт | Форма из 43 вопросов до первой ценности нарушает Закон 1, а бесплатно закрытые 16 координат обнуляют маршрут: их закрывает `slice_full_map` за 1990 ₽. Банк остаётся источником добора полной карты и инструментом ручного прогона (`docs/14-state.md`, блок решений «Продукт и маршрут») |
| Подписка и срез периода | Требуют регулярных платежей и накопленной истории профиля; продавать нечего, пока нет повторных визитов |
| Срез совместимости | Требует потока второго человека целиком; дверь на карте есть, генерации в целевом состоянии нет. Решение агента, ждёт подтверждения основателя (`docs/14-state.md`, вопрос 10) |
| PDF как продукт | Печать допустима, но продуктом не является (`docs/11-ui-page-spec.md`) |
| Чат «спроси систему про себя» | Входит в подписку, которая вне цели |
| Платная реклама и закупка трафика | Добавка, не двигатель; до проверки виральности бессмысленна |
| Собственная модель или файнтюн | Интеллект продукта — в правилах и контенте, не в модели |
| Тёмная тема | Вне цели первого релиза. Токены названы по роли («текст на карточке», а не «серый»), поэтому тёмная тема позже — вторая карта значений, а не переписывание компонентов; цена отсрочки близка к нулю |

## Условие перехода к живым людям

Прогон 30 человек по `docs/09-validation.md` — последний этап маршрута, а не первый.
Основание: до готовности технической и визуальной части реакция человека измеряет не
продукт, а его черновик; переписывать тексты по реакциям на черновик — потерянная работа.

Прогон запускается только когда закрыто всё перечисленное:

- [ ] Чеклисты слоёв 1–9 этого документа закрыты полностью
- [x] Человек проходит путь от ссылки до платного отчёта сам, без участия агента и без ручных шагов
- [x] Ступень 4 и хотя бы один платный срез генерируются автоматически и проходят валидатор
- [x] Кризисный контур проверен на сквозном тесте
- [ ] Оплата работает на реальном домене, чек приходит, доступ выдаётся
- [x] Согласие, политика и оферта опубликованы
- [x] Визуальная часть закрыта: дизайн-система, карта, шеринговая картинка, адаптив, доступность, бюджеты производительности
- [ ] Воронка и трекинг ошибок работают: реакции 30 человек будет чем измерить, кроме памяти
- [x] Инструмент фиксации наблюдений готов, памятка из `docs/09-validation.md` заведена как форма
- [ ] На пяти синтетических профилях ручная приёмка текстов пройдена, эталоны лежат в `examples/`

Пока хотя бы один пункт открыт, живых людей не запускаем. Задачи прогона и калибровки —
последний этап в `docs/13-roadmap.md`.
