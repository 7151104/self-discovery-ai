# Вопросы-доборы под платные срезы

Реализация **Закона 2**: платный срез всегда требует новых ответов.
Ни один срез не собирается из тех же 11+1 вопросов, за которые человек уже получил бесплатный разбор.

## Формат вопроса

| Поле | Значение |
|------|----------|
| ID | `S1`…`Sn` внутри среза, глобально — `slice_id:S1` |
| Тип | `выбор` (A–G) · `шкала` (1–5) · `открытый` · `число` |
| Координата | какую из 16 питает |
| Зачем | что именно этот ответ даёт в отчёте |

---

## Правила для всех доборов

1. **Поведение, не гипотетика.** «Что ты сделал в последний раз», а не «как бы ты поступил».
   Единственное исключение — `decision-moment.md`, где развилка ещё не пройдена; там вопросы
   про уже сделанные приготовления, а не про намерения.
2. **Пара к самооценке.** В каждом срезе есть минимум одна пара «шкала о себе + поведенческий
   вопрос о том же». Расхождение → `self_report_mismatch` → раздел напряжения.
3. **Открытые дают язык.** 2–4 открытых на срез. Из них берутся дословные фразы в отчёт.
4. **Вопрос не должен льстить и не должен обвинять.** Ни один вариант ответа не является
   «правильным»; у каждого варианта в отчёте есть и ресурс, и цена.
5. **Порог генерации.** У каждого среза указан минимум. Не набрано → не генерировать отчёт,
   а задать уточняющие вопросы (Правило 8 из `docs/04-alignment-rules.md`).
6. **Порции.** Доборы 590 ₽ выдаются одной порцией. Доборы 1290 ₽ — двумя порциями по 10,
   между ними промежуточный блок на странице (Закон 1: ценность до следующего шага).

## Порядок работы движка

```
Оплата → выдать вопросы-доборы среза (порциями)
      → Rule Engine: доборы + бесплатный профиль → обновлённый Profile
      → проверить порог генерации
      → порог не взят  → уточняющие вопросы, отчёт не пишем
      → порог взят     → LLM: prompts/full-report-assembler.md + надстройка среза
      → блок на личной странице + новые закрытые двери
```

Промпт-надстройки: `prompts/paid-slice-templates.md`
Скоринг: `content/scoring-rules.md` + раздел «Скоринг доборов» внутри каждого файла.
