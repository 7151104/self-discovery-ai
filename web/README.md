# web/ — дизайн-система и клиент личной страницы

Этап E6 маршрута. Здесь живут токены, компоненты и витрина. Настоящий интерфейс страницы
собирается из этих компонентов в E7; `prototype/` остаётся проверкой сценария и не трогается.

```
web/
  tokens/     единственный источник значений: типографика, цвет, сетка, тени, длительности
  src/        разметка, разбор CSS, линтер стилей, контракт сервера, опора тестов
  components/ компоненты и их стили, файл в файл
  showcase/   витрина: компоненты во всех состояниях на моковых данных
  scripts/    сборка tokens.css и app.css
  dist/       собранное; в репозитории не хранится
```

## Команды

```
npm run build:web     # компиляция и сборка стилей
npm run lint:styles   # линтер стилей отдельно от тестов
npm test              # тесты движка, сервера и клиента
npm run serve         # статический сервер на localhost:5173
```

Витрина: **http://localhost:5173/web/showcase/**
Отдельный раздел: `?section=tokens|typography|input|block|map|door|payment` — по разделу
на снимок для визуальных регрессий E11-04.

## Правила, которые проверяются автоматически

1. **Ни одного литерального цвета и ни одного литерального пикселя в CSS компонентов.**
   Любая длина, цвет, радиус, тень и длительность приходят через `var(--…)`, а имя
   переменной обязано найтись в `web/tokens/tokens.ts`. Роняет `web/src/lint-styles.ts`.
2. **Русских продуктовых строк в компонентах нет.** Тексты приходят параметрами из
   `content/` (реестр микрокопии — E5-03). Проверка рендерит каждый компонент на данных без
   кириллицы и требует, чтобы в разметке кириллицы не осталось.
3. **В разметке карты нет ни чисел, ни процентов, ни имён координат.** Позиция маркера
   сводится к одной из семи именованных зон; имена координат сверяются с
   `docs/02-coordinates.md`.
4. **Три состояния полосы различаются без цвета.** Тест сравнивает стили состояний,
   выбросив все цветовые свойства.
5. **Цели нажатия не меньше 44×44 px**, считаются по дереву витрины, а не по списку
   селекторов.
6. **Вес первой загрузки** — не больше 150 КБ скриптов и 30 КБ стилей после сжатия
   (`docs/12-target-state.md`, 5.9). Считается по графу модулей от точки входа.

Чего эти проверки не ловят: переносы строк, настоящие метрики шрифта, наложения и
переполнения. Это закрывают визуальные регрессии E11-04.

## Как добавить компонент

1. `components/имя.ts` — функция, возвращающая дерево `VNode`; все тексты параметрами.
2. `components/имя.css` — стили только на токенах.
3. Состояния — атрибутом `data-state`, а не набором классов.
4. Показать во всех состояниях в `showcase/showcase.ts` и перечислить состояния в
   `showcase/showcase.test.ts`.
