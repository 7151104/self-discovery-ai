# Банк развилок — пилот «перед сценой»

Lookup only. Не LLM на лету.  
Язык: разговорный, короткий. Не литература.

**Как пользовать:** человек написал про сцену → найди `dominant_node` + `scene` → отправь блок → попроси ответ одной строкой.

---

## Сцены (как понять, что выбрать)

| scene | Человек пишет примерно |
|-------|-------------------------|
| **SHOW** | показ, отправить, сдать, презентация, финиш, выложить |
| **TALK** | разговор, созвон, критика, конфликт, «нас обсудят» |
| **DECIDE** | решить, выбрать, уйти/остаться, развилка |
| **OWN** | своё дело, side project, без дедлайна, «надо бы начать» |

---

## NODE_FINISH_FEAR — ломается на показе

### SHOW

```
Перед показом.

У тебя на финиш обычно уходит не в «ещё поработать», а в «ещё не показывать». Пока не отправил — тебя ещё не оценили. Это успокаивает. И стопорит.

Один вопрос: что страшнее — услышать «сыро» или «не нужно»?

После — одной строкой: отправил как есть / допиливал / не отправил
```

### TALK

```
Перед разговором, где может быть оценка.

В моменте ты, скорее всего, будешь соглашаться или уходить в детали — не потому что согласен, а потому что спор = показать себя. Потом будешь додумывать ответ один.

Вопрос: что ты не скажешь вслух, но уже готовишь в голове?

После: сказал / промолчал / ушёл в детали
```

### DECIDE

```
Перед решением.

Решение «отложить» для тебя часто = не решать. Так не нужно показывать результат и не нужно слышать вердикт.

Вопрос: если бы завтра надо было показать выбор кому-то одному — что бы ты выбрал уже сегодня?

После: решил / отложил / «ещё думаю» (третий раз = отложил)
```

### OWN

```
Своё дело без дедлайна.

Тут нет начальника — значит, нет и внешней точки «пора показать». Ты можешь бесконечно «готовить». Это не подготовка. Это прятаться от оценки.

Вопрос: кому одному ты мог бы показать черновик до конца недели — не когда готово, а сейчас?

После: показал / не показал / нашёл причину не показывать
```

## NODE_PLAN_VS_OPEN — держит открытым

### SHOW

```
Перед тем как «отдать» результат.

Сдать = закрыть. Закрыть = нельзя потом «а я передумал». Ты можешь тянуть с отправкой не из перфекционизма, а из страха закрыть дверь.

Вопрос: что именно ты боишься потерять, если отправишь сегодня?

После: отправил / тяну / переписываю с нуля
```

### TALK

```
Перед разговором про нерешённое.

Тебе тяжело, когда висит открытый вопрос — и ты сам оставляешь его открытым, называя гибкостью. В разговоре будешь уходить в «посмотрим», не в «решили так».

Вопрос: какую одну фразу «мы решили…» ты избегаешь произнести?

После: назвал решение / оставил открытым
```

### DECIDE

```
Перед выбором.

Ты можешь собрать ещё один круг информации — не чтобы решить, а чтобы не закрыть. Ещё один совет = ещё день без обязательства.

Вопрос: какое решение ты уже знаешь, но не хочешь зафиксировать?

После: зафиксировал / ещё «собираю мнения»
```

### OWN

```
Своё без дедлайна.

Без срока ты сам себе не ставишь финал. Проект может жить в голове годами — «ещё не время закрыть концепцию».

Вопрос: что изменится, если поставишь дату «показать v0.1» — даже себе в календаре?

После: поставил / не поставил
```

## NODE_EXTERNAL_DEADLINE — двигается только когда ждут

### SHOW

```
Перед показом по чужому сроку.

Чужой дедлайн ты, скорее всего, закроешь — может, в последний вечер. Свой бы так же не двинул. Сейчас ты в режиме «меня ждут» — используй это, но заметь: качество финиша может быть «достаточно для них», не для тебя.

Вопрос: ты делаешь это для результата или чтобы снять ожидание?

После: сдал / сдал в последний момент / не сдал
```

### TALK

```
Перед разговором, где от тебя ждут ответа.

Когда ждут — ты отвечаешь. Когда не ждут — ты молчишь. В этом разговоре от тебя, возможно, снова ждут. Ты дашь быстрый ответ, не свой.

Вопрос: что бы ты сказал, если бы никто не ждал ответа завтра?

После: быстрый ответ / своё / отложил
```

### DECIDE

```
Перед решением.

Тебе проще решить, когда кто-то снаружи сказал «надо до пятницы». Без этого решение может стоять. Сейчас есть внешний повод или его нет?

Если нет — вопрос: кому ты мог бы искусственно «пообещать» решение к дате?

После: решил / жду внешний срок / пообещал кому-то
```

### OWN

```
Своё дело.

Тут никто не ждёт. Поэтому и стоит. Не «нет времени» — нет зрителя.

Вопрос: кому ты напишешь «к пятнице покажу кусок» — одному человеку?

После: написал / не написал / сделал без обещания
```

## NODE_OVERLOAD — забирает ещё под давлением

### SHOW

```
Перед показом под нагрузкой.

Ты можешь добавить себе ещё правок — не потому что надо, а потому что объём уже большой и «ещё чуть-чуть» кажется безопаснее, чем отдать.

Вопрос: что можно убрать из показа, не убив смысл?

После: упростил и отправил / допиливал / сорвал срок
```

### TALK

```
Перед тяжёлым разговором.

Ты, скорее всего, возьмёшь на себя лишнее — согласишься, объяснишь, закроешь чужую часть. Потом будешь один с этим.

Вопрос: что ты точно не берёшь на себя в этом разговоре?

После: взял лишнее / удержал границу
```

### DECIDE

```
Перед решением в перегрузе.

Под нагрузкой решение «да всем» или «отложу» — способ не добавить ещё одну ось. Это не решение.

Вопрос: если бы у тебя было на 20% меньше дел — что бы ты выбрал?

После: выбрал / отложил / согласился на всё
```

### OWN

```
Своё дело.

Своё часто проигрывает срочному. Не потому что не важно — потому что никто не спрашивает.

Вопрос: что из чужого ты можешь не сделать сегодня, чтобы осталось 40 минут на своё?

После: сделал своё / не дошёл
```

## NODE_CRITICISM_INTERNAL — молчит, потом прокручивает

### SHOW

```
Перед показом.

Тебя может задеть «недостаточно». Ты можешь отправить «идеальную» версию — или снова отложить. Отложить = не услышать.

Вопрос: кому показать версию, которую стыдно — раньше, чем «готовой»?

После: показал раньше / дождался идеала / не показал
```

### TALK

```
Перед разговором, где могут задеть.

В моменте будешь спокоен. Потом — прокручивание. Сейчас можно одну фразу заготовить не «чтобы победить», а чтобы не остаться один с этим вечером.

Вопрос: если заденут — что ты хочешь сказать одной фразой, не через три часа?

После: сказал в моменте / прокручивал / разговор не был
```

### DECIDE

```
Перед решением.

Ты можешь выбрать вариант, где меньше шансов услышать «ты ошибся» — не лучший, а безопасный.

Вопрос: какой выбор ты делаешь, чтобы потом не оправдываться?

После: безопасный / честный / не решил
```

### OWN

```
Своё дело.

Критика своего дела больнее чужой работы — потому что это ты. Поэтому «ещё не готов» может быть щитом.

Вопрос: что самое маленькое можно показать, чтобы критика случилась раньше, пока не вложено полгода?

После: показал малое / не показал
```

## NODE_POTENTIAL_VS_DETAIL — видит возможное, буксует на деталях

### SHOW

```
Перед показом.

Ты видишь, к чему это может вырасти. Показать сейчас = показать «ещё не выросшее». Можешь тянуть, пока картинка в голове не совпадёт с файлом. Не совпадёт никогда.

Вопрос: что минимально нужно, чтобы другой человек понял идею — не всю красоту?

После: показал минимум / ждал полной картины
```

### TALK

```
Перед разговором про проект/идею.

Ты можешь увлечь возможным и раздражаться, когда спрашивают «а как именно». Они не тормозят — они просят деталь, без которой не двигается.

Вопрос: какой один скучный факт ты можешь принести в разговор?

После: принёс / ушёл в vision
```

### DECIDE

```
Перед решением.

Ты можешь выбирать вариант с большой картинкой и маленьким первым шагом — и не делать шаг, потому что картина уже дала дофамин.

Вопрос: какой первый шаг на этой неделе — скучный, но проверяемый?

После: сделал шаг / только думал
```

### OWN

```
Своё дело.

Идея живая. Детали — «потом». Дело умирает в «потом».

Вопрос: какую одну мелочь сделать сегодня — не красиво, а существует?

После: сделал / нет
```

## После развилки — всегда

Если человек ответил 2+ раза на одну scene или 3+ раза всего — можно одно сообщение про дверь:

```
Ты уже [N] раз поймал одно и то же. Это не случайность — это твой узел из разбора.

Откуда он растёт и что с ним делать — 8 вопросов, разбор, 590 ₽. Не сейчас — тоже ок.
```

Не слать, если не просил и не было «помогло».
