# Как перенести проект на другой аккаунт Cursor

## Что нельзя перенести

- **Сам Cloud Agent** — привязан к аккаунту-владельцу
- **Историю чата** автоматически — только вручную
- Ссылка https://cursor.com/agents/bc-01a07185-8d85-7333-85d2-133106afe504 работает только со старого аккаунта

## Что переносится (всё ценное)

**Весь этот репозиторий.** История чата не нужна: всё, что решено, лежит в файлах.

| Что | Где |
|-----|-----|
| Видение, архитектура, 16 координат, правила согласования, юридика, бизнес-контекст | `docs/00`–`docs/10` |
| UI-сценарий личной страницы | `docs/11-ui-page-spec.md` |
| Определение готовности на 100%, маршрут разработки, журнал состояния | `docs/12`, `docs/13`, `docs/14` |
| Полный банк 40+3, лестница 11+1, скоринг, тексты ступеней 0–4 | `content/` |
| Вопросы-доборы восьми платных срезов, цены, пороги генерации | `content/slices/` |
| Промпты LLM, включая надстройки платных срезов | `prompts/` |
| Демо-профиль и эталонный отчёт | `examples/` |
| Rule Engine и сборщик контента из markdown | `engine/` |
| Сервер личной страницы, оплата, приватность, слой генерации | `server/` |
| Клиент: токены, компоненты, витрина состояний | `web/` |
| Конвейер, выпуск, откат, резервные копии | `.github/`, `deploy/` |
| Прототип ступеней 0–4, статический сервер, линтер контента | `prototype/`, `tools/` |

## Состояние работ на момент переноса

Точное состояние всегда в `docs/14-state.md`, а список задач — в `docs/13-roadmap.md`;
здесь только общий срез. Закрыты этапы E0, E1, E2 (движок), E3 (сервер личной страницы),
E6 (дизайн-система) и серверные части E8 (оплата) и E9 (приватность). В работе слой
генерации, настоящий интерфейс вместо прототипа и остаток инфраструктуры.

Прогон на живых людях — **последний** этап маршрута (E12), а не ближайший шаг.

Проверка, что пакет переехал целиком:

```bash
npm install
npm test              # тесты движка, сервера, слоя генерации и клиента
npm run lint:content  # запрещённые формулировки во всех текстах продукта
npm run serve         # прототип и витрина компонентов на localhost:5173
```

## Пошаговая инструкция

### Шаг 1. Забрать файлы со старого агента

**Вариант A — Git (рекомендуется):**
```bash
# На старом агенте (если есть git):
git init
git add .
git commit -m "Full project handoff package"
git remote add origin https://github.com/YOUR_USER/self-discovery-ai.git
git push -u origin main
```

**Вариант B — Скачать папку:**
- В UI Cloud Agent скачай `/agent` целиком
- Или скопируй все файлы вручную

**Вариант C — Архив:**
```bash
cd /agent && zip -r handoff.zip .
```

Каталог `engine/src/generated/` и `engine/dist/` не переносятся: они собираются из
markdown командой `npm test`.

### Шаг 2. Новый аккаунт Cursor

1. Создай репозиторий на GitHub с содержимым пакета
2. **New Cloud Agent** → выбери репозиторий
3. Или **Cursor Desktop** → Open Folder

### Шаг 3. Первое сообщение новому агенту

```
Подхватываем проект AI-самопознания. Репозиторий — полный handoff.

НАЧНИ С: AGENT-BOOTSTRAP.md (прочитай полностью)
ПОТОМ: docs/14-state.md → docs/13-roadmap.md → docs/12-target-state.md
ЭТАЛОН КАЧЕСТВА: examples/demo-report-output.md

Статус: активная разработка. Архитектуру не пересматривать.
Задачу бери по идентификатору из маршрута. Живых людей пока не запускаем.

Текущая задача: [ИДЕНТИФИКАТОР ИЗ docs/13-roadmap.md, например E2-01]
```

### Шаг 4. Проверка, что агент подхватил

Попроси нового агента:
1. Назвать текущий этап и следующую задачу по `docs/14-state.md`
2. Объяснить, почему ступени 1–3 без LLM
3. Назвать dominant_node для `examples/demo-person-answers.md`
4. Сформулировать первое платное предложение для `NODE_FINISH_FEAR`

Если ответы верные и `npm test` даёт 30 зелёных — handoff успешен.

## Опционально: сохранить историю старого чата

1. Открой старый агент в браузере (старый аккаунт)
2. Скопируй ключевые сообщения или экспортируй transcript
3. Положи в `archive/original-chat-notes.md` — не обязательно, всё важное уже в репо

## После переноса — первый шаг нового владельца

1. `docs/14-state.md` — текущая точка, принятые решения, открытые вопросы к основателю
2. `docs/13-roadmap.md` — взять задачу по идентификатору, проверив, что её зависимости закрыты
3. `docs/12-target-state.md` — чем мерить готовность

Отдельного списка задач в репозитории нет: единственный маршрут — `docs/13-roadmap.md`.
Открытые вопросы из `docs/14-state.md` (юридическое лицо, платёжный провайдер,
LLM-провайдер, домен) требуют ответа основателя — их стоит закрыть первыми, они блокируют
целые этапы.
