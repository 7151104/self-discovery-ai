## Запуск

```
npm install
npm test              # движок, контент, сервер, слой генерации, клиент
npm run lint:content  # запрещённые формулировки во всех текстах продукта
npm run serve         # прототип на /prototype/ и витрина компонентов на /web/showcase/
```

После правки любого файла в `content/` пересборка не нужна вручную: `npm test` и
`npm run serve` сами пересобирают данные из markdown.

## Сервер и база

Внешних сервисов и демонов не нужно: база — файл, он создаётся при первом старте,
непринятые миграции применяются сами.

```
npm run dev:server   # http://127.0.0.1:8787 — API и живой клиент из web/dist
curl http://127.0.0.1:8787/api/health
npm run check:health # то же: код возврата 0/1, для таймера и конвейера
npm run funnel       # воронка и метрики генерации; нужен SDAI_ADMIN_SECRET
```

Личная страница открывается по `/p/{id}` на этом же сервере: отдельный `npm run serve`
для неё не нужен. `serve` остаётся витриной компонентов и историческим прототипом.

Миграции отдельной командой:

```
npm run migrate -- status      # что применено, что нет
npm run migrate -- up          # чистая база с нуля
npm run migrate -- down        # откат последней миграции
npm run migrate -- reset       # откатить всё и накатить заново
```

Настройки — только через переменные окружения. Состав описан в `.env.example`;
значений там нет, скопировать в `.env` и заполнить. Для разработки хватает
значений по умолчанию: обязательные переменные проверяются при `SDAI_ENV=production`,
и без любой из них сервер не стартует, а пишет её имя.

Воронка и метрики генерации — `GET /api/admin/funnel` и `GET /api/admin/metrics`
за секретом `SDAI_ADMIN_SECRET` (заголовок `Authorization: Bearer …`). Без секрета
ручки отвечают отказом. Печать таблицей: `SDAI_ADMIN_SECRET=… npm run funnel`.
Админки в браузере нет: клиент эти адреса не знает и не тащит.

## Шифрование и оплата

Чувствительные поля шифруются, если задан ключ:

```
npm run keygen                    # напечатать новый ключ, никуда не записывая
SDAI_ENCRYPTION_KEY=... npm run dev:server
npm run reencrypt -- status       # чем зашифрованы записи в базе
npm run reencrypt                 # переписать всё активным ключом
```

Без ключа сервер поднимается и пишет `encryption.disabled`: записи остаются
открытыми. В рабочем окружении ключ обязателен.

Платный путь проходится без денег поддельным провайдером. После `purchase`
сервер отдаёт адрес оплаты; оплату изображает команда:

```
npm run pay -- http://127.0.0.1:8787 <заказ> <платёж> <сумма>
```

Идентификатор платежа лежит в адресе оплаты из ответа `purchase`.

Что где лежит и какие есть эндпоинты — `server/README.md`.

## Структура

- `AGENT-BOOTSTRAP.md` — вход для AI-агента
- `docs/` — концепция, архитектура, UI-сценарий, цель (`12`), маршрут (`13`), состояние работы (`14`)
- `content/` — вопросы, скоринг, тексты ступеней, доборы платных срезов
- `prompts/` — промпты для LLM
- `examples/` — демо для калибровки
- `engine/` — Rule Engine: читает контент, считает координаты, выбирает узел и предложение
- `server/` — транспорт и хранение: контракт API, база, оплата, слой генерации
- `web/` — клиент: токены, компоненты, витрина состояний страницы
- `deploy/` — выпуск, откат, служба, копии базы и проверка доступности
- `prototype/` — ранняя личная страница на движке, заменяется настоящим интерфейсом
