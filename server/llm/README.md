# Слой LLM

Генерация текстов, которые нельзя собрать lookup-таблицей: финал лестницы
(ступень 4) и, дальше по маршруту, платные срезы. Задачи маршрута — E4 в
`docs/13-roadmap.md`.

Слой чистый и вызываемый: **функции на вход-выход, без HTTP.** Очередь
заданий, статус ожидания и переживание перезапуска живут на сервере
(`server/src/generation.ts`, E4-03). Журнал вызовов и себестоимость профиля
пишет сервер из чисел, которые слой возвращает (E4-10). Кэш по хешу входа
считает слой (`input-hash.ts`), а хранит сервер (E4-11).

```
engine → LlmTask → buildStep4Prompt → провайдер → parseModelOutput
                                                    → validateText
                                                    → checkRegisters
                                                    → { блок, сюжет } | отказ
```

## Что закрыто

| Задача | Что сделано |
|--------|-------------|
| E4-01 | Порт провайдера, поддельный провайдер, таймауты, повторы, предел себестоимости профиля |
| E4-02 | Сборка промпта ступени 4 из `content/step4-open-synthesis.md` |
| E4-03 | Хеш входа для очереди: слой считает ключ, очередь живёт на сервере |
| E4-04 | Валидатор выхода: реестр запретов, методики, объём по типу отчёта, Barnum, советы |
| E4-05 | Сверка регистров речи с confidence координат по структурированному выходу |
| E4-07 | Машинный сюжет для координаты 15 с отклонением невалидного выхода |
| E4-09 | Изоляция открытого ответа от инструкции и проверка выхода на перехват |
| E4-10 | Слой отдаёт фактическую стоимость вызова; потолок сверяется с суммой журнала |
| E4-11 | Хеш стабильного входа (промпт + версия контента) для кэша на стороне сервера |
| E4-12 | Рабочая заглушка провайдера: собирает валидный выход из задания и стоит по умолчанию в запущенном сервере |

Вопрос 5 закрыт: настоящий адаптер — `openrouter` (`anthropic/claude-sonnet-5`).
По умолчанию в CI и без ключа остаётся заглушка. Очередь, журнал стоимости и кэш
на стороне сервера закрывают E4-03, E4-10 и E4-11: слой по-прежнему ничего не
пишет в базу.

## Как вызвать

```ts
import { buildPage } from "../../engine/dist/index.js";
import { FakeProvider, generateLadderFinal, loadLlmConfig } from "./dist/index.js";

const page = buildPage(person, answers);
if (!page.llmTask) return; // открытый ответ короче 15 слов: движок задания не даёт

const config = loadLlmConfig();
const outcome = await generateLadderFinal({
  task: page.llmTask,
  provider: new FakeProvider({ turns: [{ kind: "ответ", text: "…" }] }),
  retry: config.retry,
  cost: config.cost,
  spentKopecks: 0, // сумма фактических стоимостей из журнала вызовов этого профиля

});

if (outcome.ok) {
  // outcome.block          — блок ступени 4 для страницы
  // outcome.storyline      — готов к передаче движку как ProfileOptions.storyline
  // outcome.costKopecks    — что записать в журнал стоимости
  // outcome.warnings       — места, которые реестр оставляет человеку
} else {
  // outcome.reason: предел стоимости | провайдер | машинный выход | перехват |
  //                 текст | регистры | сюжет
}
```

Сервер обязан складывать `costKopecks` по профилю из журнала вызовов и приносить
сумму обратно в `spentKopecks`. Потолок считается по фактически потраченному:
если журнал уже исчерпал предел, следующий вызов не делается даже при нулевой
оценке. Слой ничего не помнит между вызовами.

## Порт провайдера

Наружу смотрит интерфейс `GenerationProvider`. Для тестов с ходами лежит
`FakeProvider`. Для CI и машины без ключа по умолчанию — заглушка `StubProvider`:
она не модель, а собирает структурно правильный ответ из самого задания. Живая
литература — `OpenRouterProvider` (`SDAI_LLM_PROVIDER=openrouter`). Имена
рабочих реализаций — в реестре `registry.ts`. Тот же приём, что у базы и
платежей: смена реализации — это новый модуль, а не правка вызывающего кода.

Порт сознательно ничего не знает о продукте: на вход текст инструкции, текст
данных, ожидаемая форма ответа и потолок выхода; на выход текст, расход токенов и
имя модели. Всё продуктовое знание — выше, в `prompt.ts` и `validator.ts`.

Адаптер OpenRouter — один модуль `openrouter-provider.ts`:

1. HTTP-вызов встроенным `fetch`, с `signal` из аргумента — таймаутом управляет
   `runner.ts`, провайдер его не заводит;
2. раскладка кодов ответа: `429`, `408`, `409`, `5xx`, обрыв сети →
   `временный отказ` (повторяется); `401`, `403`, `400`, пустой ответ →
   `постоянный отказ` (не повторяется);
3. `pricing` из настроек; нули у OpenRouter означают прайс Sonnet 5
   (20 000 / 100 000 копеек за миллион токенов при 100 ₽/$);
4. отказ стартовать без `SDAI_LLM_API_KEY`: проверяет адаптер, а не общие
   настройки;
5. имя `openrouter` в реестре `registry.ts`.

Ключ из окружения в адаптер передаёт `createLlmRuntime` — это одна строка на
стороне сервера, без которой адаптер не собрался бы. Смена модели — переменная
`SDAI_LLM_MODEL`, без нового модуля. Тесты адаптера подставляют `fetch` и в сеть
не ходят. Второй провайдер, написанный прямо в `provider.test.ts`, по-прежнему
показывает, что `runGeneration` не привязан к одной реализации.

## Переменные окружения

Ключ в репозитории не лежит и лежать не может. Список пока живёт здесь, а не в
`.env.example`: почему — в самом `.env.example`, раздел «Слой генерации».

| Переменная | По умолчанию | Что задаёт |
|------------|--------------|------------|
| `SDAI_LLM_PROVIDER` | `stub` | Реализация порта. `stub` — заглушка; `openrouter` — Claude Sonnet 5 |
| `SDAI_LLM_MODEL` | — | Модель у провайдера. Пусто — имя из самой реализации (`anthropic/claude-sonnet-5` у OpenRouter) |
| `SDAI_LLM_API_KEY` | — | Ключ провайдера. Единственный секрет сервиса |
| `SDAI_LLM_TIMEOUT_MS` | `60000` | Предел ожидания одной попытки |
| `SDAI_LLM_ATTEMPTS` | `3` | Всего попыток, включая первую |
| `SDAI_LLM_BACKOFF_MS` | `500` | Пауза перед второй попыткой |
| `SDAI_LLM_BACKOFF_FACTOR` | `2` | Во сколько раз растёт пауза |
| `SDAI_LLM_PRICE_INPUT_KOPECKS_PER_MTOK` | `0` | Цена входа. Ноль — «не задана» |
| `SDAI_LLM_PRICE_OUTPUT_KOPECKS_PER_MTOK` | `0` | Цена выхода. Ноль — «не задана» |
| `SDAI_LLM_PROFILE_COST_LIMIT_KOPECKS` | `3000` | Предел себестоимости профиля |

Предел себестоимости — 30 ₽ на профиль: около пяти процентов самого дешёвого
среза маршрута (590 ₽). Вопрос 5 это число подтвердил; переменная остаётся, если
прайс модели изменится.

Чтобы живой сервер писал литературу, а не заглушку: аккаунт на
[openrouter.ai](https://openrouter.ai), ключ, оплата (из РФ нужна иностранная или
виртуальная карта — это действие основателя), затем

```
SDAI_LLM_PROVIDER=openrouter
SDAI_LLM_MODEL=anthropic/claude-sonnet-5
```

Ключ — в `SDAI_LLM_API_KEY`, в файл описания он не пишется.

и перезапуск. Браузеру человека VPN не нужен: страница говорит только с нашим
сервером, сервер — с OpenRouter. Ключ в репозиторий не кладём.

## Границы слоя

- **Провайдер виден только через порт.** Ни одного обращения к сети вне
  реализации порта. Тесты сценариев отказа идут на `FakeProvider`; тесты
  OpenRouter подставляют `fetch`. Запущенный сервер по умолчанию поднимает
  заглушку; `openrouter` без ключа не стартует.
- **Задание модели — из контента.** `content/step4-open-synthesis.md` входит в
  промпт дословно. Слой добавляет только машинный контракт ответа и правила
  обращения с данными — ни одного правила о том, что писать о человеке.
- **Пользовательский текст не склеивается с инструкцией.** Открытый ответ живёт
  в конверте с одноразовой границей и экранирован.
- **Эшелон 3 не называется даже внутри.** Названий методик нет ни в инструкции,
  ни в данных промпта; в выходе их снимает валидатор.
- **Координата 15 заполняется только проверенным сюжетом.** Невалидный машинный
  выход отклоняется, а не пишется в профиль. Полосы карты сюжет не меняет:
  координаты 15 среди семи полос нет — открытый вопрос 24 в `docs/14-state.md`.
- **Слой сам базу не пишет.** Хеш входа и стоимость вызова он считает и отдаёт;
  очередь, журнал и кэш хранит сервер.

## Файлы

| Файл | Что делает |
|------|------------|
| `index.ts` | Что слой отдаёт наружу: сервер импортирует только это |
| `provider.ts` | Порт: интерфейс, виды отказа, расчёт и оценка стоимости |
| `registry.ts` | Реестр имён: `stub` и `openrouter` |
| `stub-provider.ts` | Рабочая заглушка: валидный машинный выход из самого задания |
| `openrouter-provider.ts` | Адаптер OpenRouter: Sonnet 5, пин Anthropic, без мышления |
| `failure-notes.ts` | Причины отказа без фразы человека: для журнала `generation.failed` |
| `fake-provider.ts` | Поддельный провайдер для тестов: ответ, временный отказ, постоянный отказ, зависание, журнал вызовов |
| `runner.ts` | Таймаут, повторы, предел себестоимости по фактически потраченному |
| `input-hash.ts` | Стабильный хеш входа: промпт плюс версия контента, без одноразовой границы |
| `config.ts` | Настройки из переменных окружения |
| `content.ts` | Чтение правил из markdown: объём, маркеры регистров, потолки confidence |
| `prompt.ts` | Сборка промпта ступени 4 из задания движка |
| `isolation.ts` | Конверт пользовательского текста, экранирование, признаки перехвата |
| `output.ts` | Машинный контракт ответа и его разбор |
| `registers.ts` | Регистр речи против confidence координаты |
| `validator.ts` | Валидатор текста по реестру, объёму и каркасу |
| `step4.ts` | Финал лестницы целиком: от задания движка до блока и сюжета |
| `text.ts` | Слова, предложения, абзацы, приведение к сравнимому виду |
| `engine.ts` | Единственная точка входа в движок: слой не ходит в его модули напрямую |
| `fixtures.ts` | Демо-человек и заведомо хороший выход для тестов |
