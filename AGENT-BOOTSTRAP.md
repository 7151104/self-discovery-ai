# BOOTSTRAP: инструкция для нового агента

Ты подхватываешь проект **в активной разработке**. Вся ценность — в этом репозитории. Не пересматривай архитектуру без явного запроса основателя.

---

## Кто основатель и как с ним работать

- Русскоязычный рынок, потом международный
- Основатель — **разработчик**, не хочет быть лицом бренда
- Ценит: согласованность моделей, маршрут отчётов («платная клиника»), качество результата, виральность через артефакт
- Не любит: воду, Barnum-эффект, «тест из журнала», огромный вход, витрину из 10 продуктов
- Решения принимай сам как product+tech lead, но **архитектуру координат и лестницу входа не ломай**

---

## Что это за продукт (одним абзацем)

AI-сервис, который собирает портрет человека через **16 внутренних координат**, питая их из десятков моделей (психология, типологии, символика), но **никогда не смешивая их в тексте**. Пользователь проходит лёгкий вход порциями, получает личную страницу с разбором, видит закрытые «двери» и покупает срезы по мере необходимости. Деньги — в маршруте, не в одном отчёте.

---

## Главный принцип (если забудешь всё — помни это)

**Модели → координаты → текст.**  
Модели не разговаривают с пользователем. Координаты — единственный язык между моделями и отчётом. Названия MBTI, Human Design, астрологии, эннеаграммы **наружу не выходят**.

## Как генерировать контент

### Ступени 1–3 (бесплатный вход)
**НЕ использовать LLM.** Только готовые тексты из `content/step1-branches.md`, `step2-branches.md`, `step3-contradictions.md`. Выбор по варианту ответа + матрица пар.

### Ступень 4 (открытый вопрос)
LLM по инструкции `content/step4-open-synthesis.md`. Вход: координаты + узел + открытый текст.

### Полный разбор / платные срезы
LLM по `prompts/full-report-assembler.md`. Сначала посчитать профиль по `content/scoring-rules.md`, потом писать.

### Регистры речи (жёстко)
- Высокая уверенность → утверждение
- Средняя → вероятность + проверяемый признак
- Низкая → вопрос
- Символический слой → только низкая уверенность, только вопросы

## Запреты (встроены в продукт)

- Диагнозы, психиатрические термины, медицинские советы
- Предсказания событий и сроков
- Слова: предназначение, энергия, миссия, вибрации, карма
- Названия методик и типологий в тексте для пользователя
- Barnum («ты глубокая натура», «много потенциала»)
- Вердикты совместимости («сходитесь/не сходитесь»)
- Витрина из многих продуктов на первом шаге оплаты
- Один большой тест на входе (35 вопросов залпом)

## Два закона продукта

**Закон 1:** ценность выдаётся **до** запроса следующего шага.  
**Закон 2:** платный срез **всегда** требует новых ответов.

## Техническая логика (для кода)

```
Ввод (имя, дата, ответы)
  → Rule Engine (scoring-rules.md) → Profile {16 coords × value, confidence, source}
  → Step 1-3: lookup tables (готовые тексты)
  → Step 4 / Paid: LLM + prompts/ + Profile
  → Page blocks (накапливаются)
  → Next step selector (по главному узлу)
```

Интеллект продукта = **текстовые правила и контент**, не код. Код — водопровод.

Реализовано в `engine/`. Markdown остаётся источником правды: сборщик
(`engine/scripts/build-content.mjs`) читает `content/*.md` и превращает в типизированные
данные. В коде живут только условия срабатывания узлов и арифметика скоринга — прозой
их однозначно не записать. Тесты сверяют состав кода с контентом, поэтому текст можно
править в markdown, не трогая код.

```
npm install
npm test        # 30 тестов, включая сквозной прогон демо-человека
npm run serve   # прототип ступеней 0–4 на localhost:5173
```
